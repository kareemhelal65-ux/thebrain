Every component below has a free tier that covers demo-scale usage (2–3 test accounts, no real concurrent users). Total spend: $0.

 Cursor (free tier) as primary IDE, Claude.ai (free tier) for architecture decisions and hard problems, GitHub Copilot (free tier) for completions, ChatGPT (free tier) for quick debugging.

Integrations:
 Google Cloud Console (free) — Google Meet API, Google Drive API, Google Calendar API, Gmail API. Slack API (free). All OAuth flows are free. Microsoft 365, Zoom, Notion, Linear, HubSpot — all cut from demo, added post-raise.

2. The Brain — Core Context Layer (v2.0 Deepened)
The Brain's memory architecture is upgraded from a two-layer model to a four-layer model. Each layer serves a distinct retrieval purpose and together they create a memory system that becomes exponentially more useful the longer a company uses it.

2.2 Knowledge Graph Engine [NEW]
Why this matters
Claude for Small Business stores context as flat files. The Brain v2.0 stores it as a living graph of entities and relationships. This is the architectural feature that cannot be replicated by any chat tool — it requires months of accumulated company data to become valuable.
Every entity extracted from ingested content is stored as a graph node with typed relationships:
Person nodes: name, role, email, department, tenure — linked to every meeting they attended, document they authored, and decision they were part of
Project nodes: linked to all related meetings, documents, action items, team members, and timeline events
Decision nodes: the most valuable entity type — stores what was decided, when, by whom, what alternatives were rejected, and what the outcome was
Document nodes: linked to the people who created and edited them, the projects they relate to, and the meetings where they were discussed
Graph traversal queries unlock retrieval patterns impossible with flat vector search:
"What has Kareem decided about pricing in the last 90 days?" — traverse Person -> Decision edges filtered by date and topic
"Who knows the most about the investor onboarding process?" — find the Person node with the most edges to Meeting and Document nodes tagged investor-onboarding
"What open action items are blocking Project X?" — traverse Project -> ActionItem edges filtered by status=open
Graph schema (core entities)
Nodes:  Person | Project | Decision | Document | Meeting | ActionItem | Topic
Edges:  ATTENDED(Person->Meeting) | AUTHORED(Person->Document)
        MADE(Person->Decision) | ASSIGNED(Person->ActionItem)
        RELATES_TO(Document->Project) | RAISED_IN(Decision->Meeting)
        BLOCKED_BY(ActionItem->ActionItem) | TAGGED(Any->Topic)
2.3 Memory Health System [NEW]
The moat mechanism
Every week The Brain runs in a company's environment, it becomes harder to leave. The Memory Health System makes this quantifiable — it shows admins a memory score, coverage percentage, and gap analysis. This is the retention mechanic that turns a product into infrastructure.
The Memory Health System runs a nightly background job that evaluates the quality and coverage of each tenant's knowledge base. It produces a Memory Health Score (0–100) computed from:
Coverage: what percentage of connected tools have been actively ingested in the last 7 days
Freshness: how recently each integration's data was updated vs. its expected update frequency
Density: number of entity nodes and relationships per active team member (measures graph richness)
Gap detection: identifies topics or people with low knowledge density — surfaces as recommendations
The Health Dashboard (admin-only UI surface) shows:
Overall memory score with trend line (week-over-week)
Per-integration coverage indicators — which tools are feeding The Brain well vs. which are stale
Top knowledge gaps: "We have very little context on the Legal team's work — connect Notion or upload their documents"
Memory age distribution: what percentage of the knowledge base is less than 30 / 90 / 180+ days old
3. Proactive Intelligence Layer [NEW]
The category-defining feature
Every competitor — including Claude for Small Business — is reactive. Users ask a question and get an answer. The Brain v2.0 is the first SMB AI OS that proactively surfaces insights the user didn't know to ask for. This is the feature that makes The Brain feel like an operating system rather than a search tool.
The Proactive Intelligence Layer runs as a background service that continuously analyses The Brain's accumulated context and surfaces three types of proactive outputs:
3.1 Daily Briefing Engine
Every morning at a user-configured time (default: 8am local), The Brain generates a personalised briefing for each user based on their role and the company's accumulated context. The briefing is delivered as a digest card in the app and optionally as a Slack message.
Briefing content is role-personalised:
Role
Briefing content
Admin / CEO
Overdue action items across all teams, decisions made yesterday, meetings happening today with pre-pulled context, open questions from last 7 days
Member
Your open action items, meetings you're attending today with relevant past context, documents shared with you this week
3.2 Anomaly & Pattern Detection Engine
Runs nightly as a Celery beat job. Scans the Knowledge Graph for patterns that merit surfacing proactively. Outputs are held in a recommendations table and surfaced as notification cards in the app.
Detected patterns (v2.0 MVP set):
Stale action items: action items assigned in a meeting with no follow-up evidence in subsequent meetings or Slack threads — flagged after 7 days
Decision drift: a decision recorded in The Brain is later contradicted by a document or Slack thread — surfaces a conflict alert for the admin
Meeting without follow-up: a meeting ended 48 hours ago with no follow-up email, no tasks created, no Slack summary — triggers the Meeting Follow-Up Agent automatically
Relationship gaps: two people who work on the same project have never appeared in the same meeting or Slack thread — flagged as a potential coordination risk
Knowledge concentration risk: a critical project's knowledge is concentrated in one person's documents and meetings — flagged for knowledge distribution
3.3 Pre-Meeting Intelligence Briefing
When a calendar event is detected (Google Calendar or Outlook Calendar), The Brain automatically generates a briefing card 15 minutes before the meeting starts. The briefing is pushed to the app and optionally to Slack.

5. The Orchestrator (v2.0 Improvements)
The Orchestrator is upgraded with two new capabilities: graph-aware context retrieval (so the planner receives entity relationships alongside vector chunks) and a cost routing layer that automatically selects the cheapest model capable of the task.
5.1 Graph-Aware Context Retrieval [NEW]
When a user sends a prompt, the Orchestrator now runs a three-stage context build:
Stage 1 — Vector retrieval: hybrid semantic + BM25 search, top-8 chunks as before
Stage 2 — Graph expansion: for each retrieved chunk, query the Knowledge Graph for related entities (1-hop neighbours). Add decision nodes, person nodes, and project nodes linked to the retrieved content. This adds structured context the vector search cannot surface.
Stage 3 — Context assembly: merge vector chunks and graph entities into a unified context window, ranked by combined relevance score. The LLM planner receives richer, more structured context than any flat RAG system can provide.
5.2 Model Cost Router [NEW]
Cost efficiency at scale
LLM API costs are the #1 scaling risk for The Brain. A naive implementation sends every query to GPT-4o or Claude Sonnet — expensive at scale. The Cost Router automatically routes each task to the cheapest model that can handle it, reducing LLM spend by an estimated 55-70% at beta volumes.
Routing logic (in order of evaluation):
Simple Q&A (confidence > 0.85, context < 1K tokens) — Claude Haiku or GPT-4o mini (~$0.15/MTok). Covers ~50% of queries.
Complex reasoning (multi-step, context 1K-8K tokens) — Claude Sonnet 4.6 or GPT-4o. Covers ~40% of queries.
Deep synthesis (cross-document analysis, context > 8K tokens) — Claude Opus 4.6 or GPT-4o. Covers ~10% of queries.
Entity extraction (Step 8 of ingestion pipeline) — Claude Haiku exclusively. Low complexity, high volume, cost-critical.

The v1.0 audit log is an append-only table. The v2.0 audit log adds cryptographic signing:

12. Appendix — New Technical Decisions
Why Apache AGE over Neo4j for the Knowledge Graph?
Neo4j is the standard graph database but it requires running a separate service alongside PostgreSQL. Apache AGE is a PostgreSQL extension that adds full Cypher query language support directly inside the existing RDS instance. For a 3-person engineering team, eliminating one managed service removes one ops burden, one failure mode, one cost line, and one security surface. The performance difference is negligible at the data volumes The Brain will handle in Phases 1 and 2 (< 1M nodes). At Phase 4 scale, migrate to dedicated Neo4j Aura if graph query latency becomes an issue.
Why Plasmo for the browser extension?
Plasmo is a modern browser extension framework (React + TypeScript) that handles the boilerplate of Chrome/Firefox extension manifest v3, background workers, and content scripts. It builds to both Chrome and Firefox from the same codebase. The alternative (raw manifest v3 + Webpack) adds 2-3 weeks of setup work with no product value. Plasmo is MIT-licensed and actively maintained.
Why move pre-meeting briefing to Phase 1?
The original roadmap put pre-meeting briefing in Phase 3 because it felt like a polish feature. After the Anthropic launch analysis, it is now clear that this is the single most viscerally compelling demonstration of what persistent memory enables — and it is the hardest feature for any competitor to replicate without an accumulated knowledge base. It must ship in Phase 1 so that the 3 internal beta users experience it immediately and can speak to it authentically in investor and customer conversations.
Why spaCy for NER instead of a pure LLM approach?
Running every ingested document through a large LLM for entity extraction is 10-20x more expensive per document than running spaCy's transformer-based NER model. spaCy handles Person, Organisation, Date, and Location extraction reliably at high speed and very low cost. Claude Haiku handles the harder extractions (Decision, ActionItem) that require reasoning, not just pattern matching. The two-pass approach gives the accuracy of LLM extraction at a fraction of the cost.
